# NASA Space Apps submission / provenance checklist

This is a current checklist, **not a declaration of eligibility approval**.

- [ ] Obtain and record specific written official guidance concerning any challenge-specific code developed **before the hackathon**; preserve original commit timestamps and authorship. See [prototype provenance](prototype-provenance.md).
- [ ] Recheck the official 2026 competition terms, submission, links and required AI-use attributions.
- [x] Original SurfaceSignal software/docs carry an explicit **Apache-2.0 LICENSE** and NOTICE. Third-party datasets/assets keep their own terms.
- [ ] The GitHub repository's **visibility** must be checked separately before claiming public code access; a public website does not make a private repo readable to judges.
- [x] Public scientific data package records 19 NISAR acquisitions / 17 comparisons and source attribution.
- [x] Actual contextual sources documented: CHIRPS v3 SAT, JRC GSW v1.5, ESA WorldCover, Copernicus DEM, IBGE 2022 and SGB.
- [ ] Independent field/spatial validation **not completed**. Do not state that radar candidates are confirmed flooding.
- [ ] Verify AI-generated visual attribution, source image rights, accessibility and the exact submission declarations.
- [ ] Run CI, security review and credentials/restricted-data checks before making repository history public.

A license update does **not** resolve the documented question of pre-event development.
