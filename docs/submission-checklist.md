# NASA Space Apps Challenge — project submission checklist

Use the [official team/project page](https://www.spaceappschallenge.org/2026/find-a-team/sudo-nova/?tab=project) and the published 2026 rules for submission requirements.

- [ ] Verify submission status, project website, presentation, language links and demo access.
- [ ] Check repository visibility; a working public website does not make a private GitHub repository visible to reviewers.
- [x] Add [Apache-2.0](../LICENSE) for original software/docs with [NOTICE](../NOTICE) for independently licensed data/assets.
- [x] Explain 19 real NISAR scenes, 17 temporal comparisons and scientific limitations.
- [x] Attribute actual context: CHIRPS v3 SAT, JRC GSW, ESA WorldCover, Copernicus DEM, IBGE and SGB.
- [ ] Check redistribution rights for native source data, third-party map imagery and visual assets.
- [ ] Review AI-generated content disclosures against current contest rules.
- [ ] Avoid claiming radar candidates are confirmed floods, damages, operational warnings or externally validated classifications.
- [ ] Run CI and check source files/export assets for credentials or restricted imagery.

This checklist does not substitute for official competition requirements. An open-source license does not certify contest acceptance.
